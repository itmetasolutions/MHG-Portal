# Agent Portal Revamp Handoff

## Final Business Logic

The agent portal is owned-agent scoped. Agents see and act only on records owned by their user id: landlords via `ownerAgentId`, properties via `ownerAgentId`, tenants via `addedByAgentId`, potential tenants via `addedByAgentId`, potential landlords via `addedByAgentId`, call logs via `agentId`, sales via `closedByUserId` or the property owner, and reports via `agentId`.

The dashboard landlord lookup is the first step for landlord workflows. A searched number is normalized and logged. If it belongs to another agent, show an exists/conflict result and notify the owner. If it belongs to the current agent, show Add Property against that landlord only. If it does not exist, show Start, which opens only Interested, Not Interested, and Follow Up.

Postcodes are uppercase on input and before persistence. Rent per week is derived from rent per month using `(monthly * 12) / 52`, rounded to 2 decimals. Property references are generated by the server.

## Role Permissions

Agent:
- Can see only their own landlords, properties, tenants, potential tenants, potential landlords, sales, call logs, contacts, and daily reports.
- Can add properties only against their own existing landlords.
- Can create landlords only through Interested or Follow Up flows.
- Can close sales only on their own properties.
- Can publish/unpublish only their own properties.

Admin:
- Can see all records.
- Can filter by agent.
- Retains existing commission split configuration.
- Can see each agent's daily reports.

## Page Behavior

Dashboard:
- Shows existing stats.
- Shows landlord number lookup.
- Lookup outcomes: other agent conflict, own landlord Add Property, new number Start.

Start:
- Requires a checked phone number.
- Shows exactly three options: Interested, Not Interested, Follow Up.
- Not Interested logs a `CallLog` with `NOT_INTERESTED` and returns to dashboard.

Interested:
- Shows Landlord Form and Property Form.
- Creates landlord if not already owned by current agent.
- Creates property.
- Logs `CallLog.CONFIRMED`.
- Auto-adds landlord to contacts.

Follow Up:
- Shows Landlord Form and scheduled date/time.
- Creates/updates Potential Landlord.
- Locks the lead until scheduled time plus 1 day.
- Logs `CallLog.FOLLOW_UP`.
- Auto-adds landlord to contacts.

Properties:
- Agents see only owned properties.
- Add button must show existing owned landlord list first, then Property Form.
- Each property needs Close Sale and Publish to Web controls.

Landlords:
- Agents see only owned landlords.
- No direct add button.

Tenants:
- Closed tenants only.
- Created from Close Sale only.
- Agents see only their own tenants.

Potential Tenants:
- Add Potential Tenant button opens Tenant Form.
- Agents see only their own potential tenants.

Potential Landlords:
- Follow-up landlords only.
- Continue returns to Start with the phone and potential landlord id.

Daily Reports:
- Generated from portal data only.
- No manual report form.

## Field Validations

Landlord:
- First Name required.
- Last Name required.
- Phone required and normalized.
- Email optional and valid when present.

Property:
- Photos required, at least one, alt text supported.
- Description required.
- Post Code required and uppercase.
- City required.
- Availability Date required.
- Initial Status is Draft or Active.
- Private Property requires rent/month, auto rent/week, deposit, expected commission, category, and all yes/no fields.
- Studio Flat hides No of Rooms and Available Rooms.
- Shared Property requires at least one room row.
- Room rows require room type, rent/month, auto rent/week, deposit, expected commission.

Tenant:
- All listed required fields must be enforced.
- Current living postcode and workplace postcode uppercase.

## Workflow States

Lookup states:
- `FOUND_OTHER`
- `FOUND_OWN`
- `NOT_FOUND`

Call states:
- `CONFIRMED`
- `NOT_INTERESTED`
- `FOLLOW_UP`

Property states:
- `DRAFT`
- `AVAILABLE`
- `CLOSED`

Room states:
- `AVAILABLE`
- `UNDER_OFFER`
- `CLOSED`

Potential landlord lock:
- Locked from Follow Up submission until `scheduledAt + 1 day`.
- Other agents cannot convert or create against the same normalized phone while locked.

## Notifications And Reminders

Owner search conflict:
- Create notification for owning agent when another agent searches their landlord number.
- Existing email notification may remain.

Follow-up reminders:
- Email agent 1 hour before scheduled time.
- Email agent 5 minutes before scheduled time.
- Portal notification/ringing reminder 5 minutes before scheduled time.
- Use `reminder1hSent` and `reminder5mSent` to avoid duplicates.

## Reporting Logic

Daily reports are derived from:
- `LandlordLookupLog` for total numbers searched.
- `CallLog` for calls made, confirmed, not interested, follow up.
- Dialer/call records for calls connected/failed where relevant.
- `PotentialTenant` for potential tenants.
- `Sale` for sales closed.
- `Property`/`CallLog.CONFIRMED` for properties confirmed.

Agents can see only their own rows. Admin can filter and view by agent.

## Edge Cases

- Existing landlord owned by another agent: block creation and property add.
- Existing landlord owned by current agent: skip landlord creation and allow property add.
- Locked potential landlord: block other agents until `lockedUntil`.
- Expired lock: new agent can proceed after scheduled time plus 1 day.
- Shared property close sale must happen per room.
- Private property close sale must happen at property level.
- Already closed property or room cannot be closed again.
- Missing photos blocks property creation and publishing.
- Publishing must check ownership.
- Postcodes entered lowercase must persist uppercase.

## Recommended Database Structure

Current schema already supports most of this:
- `User`
- `Landlord.ownerAgentId`
- `Property.ownerAgentId`
- `PropertyMedia.altText`
- `PropertyRoom`
- `Tenant.addedByAgentId`
- `PotentialTenant.addedByAgentId`
- `PotentialLandlord.addedByAgentId`, `scheduledAt`, `isLocked`, `lockedUntil`, reminder flags
- `CallLog`
- `LandlordLookupLog`
- `DailyReport`
- `Notification`
- `DialerContact`
- `CommissionConfig`

Recommended additions:
- Add `publishedAt` and `publishedById` to `Property`.
- Add a first-class `PropertyType` enum for `PRIVATE` and `SHARED` instead of relying on `VacancyType` labels.
- Add `CallLog.lookupLogId` for direct traceability.
- Add `DailyReport.generatedFrom` JSON metadata for auditability.

## Deprecated Old Logic

- Direct landlord add outside Start Interested/Follow Up.
- Direct tenant add outside Close Sale.
- Manual call logging for workflow outcomes.
- Manual daily reporting.
- Start page options before number lookup.
- Property creation against another agent's landlord.
- Cross-agent agent views for agent pages.
- Old Not Interested instruction card that did not log automatically.
- Publish endpoint without ownership enforcement.

## Retained Old Logic

- Dashboard stats, where still relevant.
- Admin-set commission split logic.
- Templates system.
- Contacts system, extended by auto-adding Interested and Follow Up landlords.
- Existing notification bell/dropdown.
- Existing chat system.

## Developer Notes

- Prefer enforcing ownership in server routes and server components, not just client filters.
- Any new agent page query must include the agent ownership predicate.
- Keep all workflow writes in transactions: entity creation, call log, audit log, contact creation where possible.
- Treat API routes as the source of truth for validation.
- UI should hide deprecated add paths, but API routes must also reject them.
